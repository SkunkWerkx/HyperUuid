# Go: the core translated by wasm2go — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Go binding's cgo backends and committed archives with one committed Go translation of the core, regenerated and diffed in CI, tested under stock Go, TinyGo and Go's wasm targets, with the Forge and docs following.

**Architecture:** `rust/` is built for `wasm32-wasip1` by a pinned rustc and translated by a pinned wasm2go into `go/internal/core/core.go`. `go/core.go` owns one primary instance (v7 and its counter) plus a pool of instances for stateless calls, a scratch region in guest memory, and the WASI `random_get` host, served by a hardened AES-256-CTR stream where Go's AES is accelerated and by `crypto/rand` elsewhere. The public API in `uuidgen.go` and `inspect.go` is untouched except that `NewV5` gains a limit.

**Tech Stack:** Go 1.26+ (`go.mod` floor), `github.com/ncruces/wasm2go` v0.4.19 (tool module), `golang.org/x/sys/cpu`, rustc 1.99.1 with `wasm32-wasip1`, TinyGo 0.44, wasmtime, node; the Forge (`../HyperForge`) for CI.

**Spec:** `docs/superpowers/specs/2026-10-31-go-wasm2go-design.md`

## Global Constraints

- **No git operations.** The owner commits, pushes, tags and dispatches. Every task leaves its work verified in the working tree of `HyperUuid` or `../HyperForge` and reports it; where a step below says "done", it means verified, not committed.
- The published module's dependencies are exactly `github.com/google/uuid` and `golang.org/x/sys`; `go.mod` keeps `go 1.26`. wasm2go lives only in `go/internal/wasm2go/go.mod`.
- The rustc pin is `1.99.1`, in `go/internal/wasm2go/rust-toolchain.toml` and nowhere else; the stack size is `65536`, a constant in the generator and nowhere else; the `-zstack-size` flag goes on the `cargo cdylib` command line, never into `rust/.cargo/config.toml`.
- AES stream selection: `accelerated()` is true only on amd64 with `X86.HasAES && X86.HasSSE41 && X86.HasSSSE3`, arm64 with `ARM64.HasAES`, s390x with `S390X.HasAES && S390X.HasAESCBC`; never under `purego`, `tinygo` or `fips140.Enabled()`. ppc64 and ppc64le take the OS source.
- Budget: 1 MiB of generated keystream or one second per key; buffer 512 bytes; key and IV in reusable storage; a failed rekey leaves the source keyless until a rekey completes.
- `MaxV5Name = min(1<<31-1, hostMaxPages*65536 - 2*65536 - 32)` with `hostMaxPages = min(65536, math.MaxInt>>16)`; all size arithmetic in `uint64` before any `int`.
- Export patterns in `check_exports.py` carry the `(?:uuid|hyperuuid)_` prefix.
- `CGO_ENABLED=0` on every ordinary Go test and portability step in CI, so a cgo dependency can never creep back; two named exceptions that reintroduce no backend: `-race` runs (the race detector needs cgo on Linux) and iOS, where Go itself requires the external linker. The Go step sits right after the Rust compile steps in `hyper-build-native.yml`.
- Every number in a README comes from the shipped binding's own benchmarks on this machine, labelled Apple M6 (Mac18,5), Go 1.27.3; the spike's numbers never appear as the binding's. x64 columns are marked as awaiting the XPS run.
- Docs state the current state only; history goes to the CHANGELOG under Unreleased. Install snippets keep `@latest`.
- A verification counts only when its negative control fails; each task names its control.

## Review Focus

- A `NewV5` name of exactly 65,504 bytes (fills the base page after the 32-byte header) must run on the primary or pool, and 65,505 bytes on a one-off instance; both return the same UUID as `google/uuid.NewSHA1`. Pinned in Task 3's `TestV5NameAtThePageBoundary`.
- A batch grow that races a pooled stateless call must not read a stale memory slice: the primary re-reads `mem()` after `Grow` under its own lock, and pooled instances never grow for batches. Pinned in Task 3's `TestBatchGrowWhileStatelessCallsRun` under `-race`.
- `GOMAXPROCS(1)` programs and TinyGo must never create a pooled instance for an uncontended call. Pinned in Task 3's `TestUncontendedCallsStayOnThePrimary` (instance count through a test hook).
- A `random_get` of zero bytes must not touch the source, and a v5 never draws. Pinned in Task 2's `TestZeroLengthDrawTouchesNothing` with a counting reader and Task 3's `TestV5DrawsNoEntropy`. (The core draws entropy before it reserves, `rust/src/v7.rs` `new_v7_batch_in`, so an exhausted stream still draws; nothing here claims otherwise.)
- A swapped `entropy` reader must not leak between tests or into the stream's rekey in another test. Pinned by Task 2's helper `withEntropy(t, r)` restoring on `t.Cleanup`, used by every injecting test.

- Produces: package `core` (`go/internal/core`) with `core.New(host Xwasi_snapshot_preview1) *Module`, `(*Module).Xmemory() Memory` (`Slice() *[]byte`, `Grow(delta, max int64) int64`), and `X<export>` methods for the thirteen exports as wasm2go emits them: `Xuuid_new_v7(v0 int64, v1 int32) int32`, `Xuuid_new_v7_batch(v0 int64, v1, v2 int32) int32`, `Xuuid_v7_unix_millis(v0 int32) int64`, `Xuuid_v7_unix_millis_in(v0, v1 int32) int64`, and the other nine taking and returning `int32`. - Produces: the generator CLI `go -C internal/wasm2go run . [-root <repo>] [-o <file>] [-stack <bytes>]`: exit 0 and the file written; exit 2 and the line `rustup toolchain install 1.99.1 --profile minimal --target wasm32-wasip1` on stderr when `cargo`, `rustup`, the pinned toolchain or its wasip1 target is missing (a prerequisite); exit 1 with the tool's output when cargo or wasm2go itself fails (a defect). `regenerationPrereqs(root string) error` in the tests checks, before anything is built or copied, that `go`, `cargo` and `rustup` are on PATH, that `<root>/rust/Cargo.toml` exists (the Rust tree is outside the Go module and is absent from a copied package directory on a mobile runner), and that `rustup run <pin> rustc -V` succeeds with the `channel` read from `internal/wasm2go/rust-toolchain.toml`; each miss returns an error wrapping `errPrerequisite` that names the missing piece, the toolchain one naming the install line. `requireRegeneration(t, root)` calls it and skips on `errPrerequisite` unless `HYPERUUID_CHECK_CORE` is set, in which case it fails. `regenerate(t, root, out)` then builds the generator into a temp executable (`go -C internal/wasm2go build -o <tmp>/wasm2go-gen .`; a build failure is a defect, since every prerequisite is already established) and runs that executable directly, so its exit status is the generator's own: `go run` would report every child failure as exit 1 and mask the distinction. Exit 2 still maps to `errPrerequisite` (the generator's own check is kept for the command line); anything else non-zero is an ordinary error carrying stderr. No stderr text is parsed. The file's build tag keeps both tests off stock Go's js and wasip1 ports, where `os/exec` returns ENOSYS from `StartProcess` before any exit code exists, and off TinyGo; the corpus and binding tests stay in the shared files and run everywhere.
