# C# `net10.0;net11.0` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A .NET 10 project restores HyperUuid and gets the same API, static link and CI receipts as .NET 11 on Windows, Linux (glibc and musl) and macOS. A .NET 10 browser, Android, iOS or Mac Catalyst build stops with `HYPERUUID003`.

**Architecture:**
- **The library, the tests and the AOT smoke test:** they multi-target from one source. Strict package validation holds the two public surfaces equal.
- **The targets file:** it moves to `build/net10.0/`, which NuGet hands to net11 too. It gains one evaluation-time gate that switches every other block off for the four platforms .NET 10 can't serve.
- **The Forge:** it gains two inert inputs: an AOT `-f` loop and a second runtime for the suites.
- **This repo:** a new `test-nuget-package` job proves the packed `.nupkg`, with a control for the silent fallback to the shared library.

**Tech Stack:** .NET SDK 11 (`global.json` rc.2 pin, rc.3 on this Mac), MSBuild, NuGet package validation, GitHub Actions, the Forge's `hyper-build-native.yml` and `musl-suite`.

**Spec:** `docs/superpowers/specs/2026-10-28-csharp-net10-design.md`. It is plan 3 of Phase 1. The order and the shared-file map are in `.superpowers/brainstorm/2026-10-28-phase1/integration.md`.

## Global Constraints

- **TFMs:** `<TargetFrameworks>net10.0;net11.0</TargetFrameworks>` in `HyperUuid.csproj`, `HyperUuid.Tests.csproj` and `HyperUuid.AotSmokeTest.csproj`, and nowhere else. Wasm, Apple, Android and Benchmarks stay `net11.0*`.
- **One source:** no `#if NET11_0_OR_GREATER` and no `LangVersion`.
- **Validation:** `<EnablePackageValidation>true</EnablePackageValidation>` and `<EnableStrictModeForCompatibleFrameworksInPackage>true</EnableStrictModeForCompatibleFrameworksInPackage>` in `HyperUuid.csproj`.
- **Package layout:**
  - present: `lib/net10.0/`, `lib/net11.0/`, `build/net10.0/HyperUuid.targets`, and `buildTransitive/net10.0/HyperUuid.targets`, which imports `../../build/net10.0/HyperUuid.targets`;
  - absent: no `build/net11.0/` and no `buildTransitive/net11.0/`;
  - unchanged: the wasm archive stays at `runtimes/browser-wasm/nativeassets/net11.0/libhyperuuid.a`.
- **Error text** (`HYPERUUID003`, verbatim):
  - The message is `HyperUuid supports .NET 10 on Windows, Linux and macOS, framework-dependent or Native AOT. {platform} needs .NET 11 or later: target {tfm}.`
  - The platform/TFM pairs are `Blazor WebAssembly`/`net11.0`, `Android`/`net11.0-android`, `iOS`/`net11.0-ios` and `Mac Catalyst`/`net11.0-maccatalyst`.
  - Browser alone appends ` .NET 10's WebAssembly toolchain cannot link HyperUuid's native core: https://github.com/dotnet/runtime/issues/132858.`
- **Names:** the gate property `_HyperUuidNet10Unsupported` and the target `_HyperUuidErrorUnsupportedNet10Platform`, with `BeforeTargets="_CheckForInvalidConfigurationAndPlatform"`. There is no opt-out property.
- **Forge inputs**, both `type: string`, `required: false`, `default: ""`:
  - `csharp_aot_frameworks`: space-separated TFMs;
  - `csharp_extra_runtime`: a channel such as `10.0`.
- **ci.yml values:** `csharp_aot_frameworks: "net10.0 net11.0"` and `csharp_extra_runtime: "10.0"`.
- **Not in this plan:**
  - `global.json`, Dependabot's `dotnet-sdk` entry, the `11.*-*` floats and `ValidateXcodeVersion`: that is the RTM switch, in its own commit. This plan adds no `ValidateXcodeVersion` use.
  - Every benchmark table and label: README :68 and `csharp/README.md` Benchmarks wait for the M6 receipts pass.
  - HyperCast and HyperTabular.
- **Git:** the owner drives it (CLAUDE.md). Implementers stage nothing and commit nothing, and use `mv`, never `git mv`, which stages.
  - The AOT smoke test's `TargetFrameworks` (Task 2) and ci.yml's `csharp_aot_frameworks` (Task 6) must reach the owner together: either alone fails every AOT leg with NETSDK1129.
- **Forge:** edits go in the `../HyperForge` working tree only, under Task 4, and need the owner's go. The Forge PR merges first, inert by default, and not while a release is in flight: `gh run list -w release.yml` in all three repos.
- **Checks:** every check names its negative control (NC). Package checks use `-p:RestorePackagesPath=$SCRATCH/packages` and a unique version per pack. Copy flags from the Forge and from ci.yml.
- **Fresh archives:** every gitignored `csharp/HyperUuid/staticlibs/{rid}/` a local check links is rebuilt first for that RID's Rust target, as in Task 2 Step 0, from a scratch copy of the checkout. That covers osx-arm64, linux-musl-arm64, the four Apple mobile RIDs (`APPLE_MOBILE=1`) and android-x64 (`ANDROID=1`). The ones in the tree predate the v7 re-seed.
- **Parity:** this changes the C# binding only. The other eight bindings and their bytes are untouched, because the core, the C ABI and the corpus don't move.

## Review Focus

1. **Where the targets file is imported.**
   - The four hand-importing projects (AOT, Wasm, Apple, `PlatformGateTest`) import it in the project body, before the SDK has set `TargetFrameworkIdentifier`, `TargetFrameworkVersion` or `TargetPlatformIdentifier` (probed: all three are empty there).
   - A NuGet consumer imports it after them.
   - The gate must fire the same way in both. Pinned: Task 1's evaluation probes (hand import) and Task 3's packed-package Blazor consumer.
2. **`net10.0-windows` (WPF, WinForms) is Windows desktop, so it's claimed.** It must not be gated, and neither must `net10.0-macos`, which is unclaimed but not refused. Pinned: Task 1's `-getProperty` probe for both.
3. **The outer build of a multi-targeted project,** where `TargetFramework` is empty, must neither error nor gate. Pinned: Task 2's `dotnet build` of the AOT smoke test with no `-f`.
4. **A net10 Blazor app that reaches the package through a net10 class library** gets `HYPERUUID003` through `buildTransitive/`. Pinned: Task 3, step 6.
5. **Framework-dependent .NET 10 from the package:**
   - With no `PublishAot`, `runtimes/{rid}/native/` must resolve.
   - `IsAvailable` must be `true`, and the smoke test must pass.
   - Pinned: Task 3, step 4.

## Spec corrections found while planning

1. **The gate can't read `TargetFrameworkVersion` or `TargetPlatformIdentifier` at evaluation.**
   - In a body import those properties are empty.
   - Probed 2026-10-28 on SDK rc.3, from a `<TargetFrameworks>net10.0;net11.0</TargetFrameworks>` project that imports a stand-in file in its body:
     - `$(TargetFrameworkVersion)` and `$(TargetPlatformIdentifier)` evaluate to `[]`;
     - `$([MSBuild]::GetTargetFrameworkVersion($(TargetFramework)))` gives `10.0`;
     - `GetTargetPlatformIdentifier` gives `ios` for `net10.0-ios`;
     - the outer build gives `Unsupported`/`0.0`.
   - A stand-in gate built on those functions raised `HYPERUUID003` first for `net10.0-ios`, `net10.0-maccatalyst`, `net10.0-android` and `net10.0`+`browser-wasm`. It left `net10.0-windows` ungated and `net11.0`+`browser-wasm` building.
   - The plan therefore derives the gate from `$(TargetFramework)` and `$(RuntimeIdentifier)`. The spec's conditions are the intent; this is their evaluable form.
2. **The `request-staging` membership is already pinned.** `test_release_mode_ci_on_master_requests_staging_of_its_own_run` (`test_workflow_contracts.py:182-190`) asserts that its `needs` equals every other job. The new test still asserts it, as the spec asks, and adds the `needs: [build-static, build-native]` shape. The spec's NC (dropping the job from `request-staging`) fails both tests.
3. **The Forge inputs fail the local contract suite until the Forge changes.** `ForgeInterfaceTests.test_calls_match_declared_inputs` (`:267-276`) checks ci.yml's `build-native` `with:` keys against `../HyperForge`'s declared inputs. So the two inputs (Task 6) can't pass the local contract suite until Task 4 is in the Forge working tree.
4. **`git mv` → `mv`,** because the owner drives git.
5. **Benchmark wording is not planned.** The spec's README :68 bullet ("measured on .NET 10") and its Benchmarks bullet contradict its own Open item 1 and the owner's decision.
6. **Stale `build/net11.0/` mentions the spec's file list misses:**
   - `csharp/README.md` :157, :161 and :186;
   - `csharp/HyperUuid.WasmSmokeTest/Pages/Home.razor:29`.

   The listed ci.yml comments are at :225 and :427 now, not :221 and :423, because plan 1 moved them. All of these are fixed here.
7. **"SDK 11 alone packs net10.0".** `global.json` selects SDK 11 either way, but a hosted image may also carry SDK 10, and this Mac has 10.0.403. The job logs `dotnet --version` and `dotnet --list-sdks`, and nothing claims SDK 10 is absent.
